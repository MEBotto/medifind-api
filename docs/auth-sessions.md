# Refresh sessions

POST /api/auth/login and /register return the existing data.user and data.token shape and set medifind_refresh (HttpOnly, SameSite=Strict, Secure in production, path /api/auth). POST /api/auth/refresh rotates the cookie and returns a new access token and user. POST /api/auth/logout revokes the family and returns 204. Use a same-origin reverse proxy in production; cross-site cookies are intentionally unsupported. ACCESS_TOKEN_MINUTES defaults to 15 (1–60), REFRESH_TOKEN_DAYS defaults to 7 (1–90), absolute family expiry. Run npm run migration:run before deployment. Existing access JWTs remain valid until expiry; logout does not immediately revoke them. Concurrent refreshes with the same token revoke the family, so clients must serialize refresh across tabs. Expired rows need periodic cleanup; retain revoked rows until family expiry for replay detection. No integration test execution verified yet.
